## Architecture status

### Control plane
- Projects, features, tasks, pitches and decisions are persisted in PostgreSQL/Prisma.
- Team Lead decisions are validated before execution.
- Agent decisions are persisted and auditable.
- Distributed loop leases prevent duplicate autonomous cycles.
- Stale decisions and agent runs have recovery paths.

### Agent workflow
Athena -> CEO approval -> Feature/Tasks -> Apollo/Hephaistos/Atlas -> Artemis -> explicit Feature QA approval -> CEO release gate -> release.

### GitHub
- Issues, branches and PRs are tracked on tasks.
- Worker agents create branches and PRs.
- Release checks PR status/checks before merge in the real runtime.
- Webhooks and synchronization reconcile external state.

## Findings still remaining

### P0 — required for true unattended production
1. Real Hermes runtime must be installed/configured on the Forge host.
2. Production deployment of Forge itself is not automated.
3. Worker execution needs stronger idempotency around external GitHub side effects.
4. Retry policy should distinguish transient infrastructure failures from deterministic code/QA failures.
5. Agent outputs should be persisted as first-class artifacts/messages for richer observability.
6. Release ownership should eventually move from the CEO-triggered feature service to Nike's release workflow while retaining the CEO gate.

### P1 — autonomy quality
1. Nike is still a release role rather than a full autonomous deployment agent; release authority is intentionally kept behind the CEO gate.
2. Research is now executed through Hermes against bounded project context; external research/search adapters are still a runtime integration concern.
3. Task assignment is role-based; specialization/capability metadata would improve routing between multiple employees with the same role.
4. Workforce utilization is currently heuristic (25% per active task) rather than based on runtime capacity.
5. Artemis currently validates task branches, but richer PR review/check annotations would improve feedback loops.
6. Memory writes need stronger project/employee scoping and automated consolidation.

### P2 — product / UX
1. Add a dedicated agent-session detail view with live messages/tool calls/artifacts.
2. Show governance reviews and blocking reasons directly in feature/task views.
3. Add explicit retry/attempt state to the task UI.
4. Add release timeline and rollback status.
5. Add agent health and runtime availability indicators.
